# Issue #242 — FactSet Insight RSS handoff

## Decision

FactSet Insightの新着記事だけを投資判断用の日本語要約へ送り、RSSに変化がないtickではLLMを起動しない。

## Uncertainty

RSS metadataの取得成功と、記事本文取得・要約・配信成功は別状態である。RSSを観測しただけでdelivery済みにすると、本文取得や配信失敗時に記事を失う。

## Evidence test

focused testとlive RSS source-healthで以下を直接確認する。

1. 現在feedをbootstrapしたstateでは`[SILENT]`。
2. stateから1 article IDだけ外すと、その1記事だけ`NEW_ARTICLE`。
3. monitor実行だけではstateは変わらない。
4. `ack`後の次monitorで`[SILENT]`。
5. malformed/partial RSSはfail closed。
6. live RSSがstrict parserを通過し、accepted snapshotとして`input_ledger` auditを通る。

## Runtime contract

通常tickはこの順序だけを使う。

```text
accepted latest_feed.json
  -> deterministic monitor
  -> [SILENT]なら終了（LLM未起動）
  -> NEW_ARTICLEのみ本文取得
  -> 日本語3〜5文要約 + JST + 原文URL
  -> delivery成功
  -> そのarticle_idだけack
```

本文取得・要約・deliveryのどこかで失敗したarticleはackしない。次tickで再試行する。

## Claim boundary

- RSS metadata: observed publisher metadata
- article body: transient source text; public Gitへ全文保存しない
- Japanese summary: derived evidence
- summary内の数値claim: article URLへ遡れること
- GDELT: discovery-only。FactSet publisher feedの代替正本にしない

## Acceptance criteria

- [ ] focused unit tests成功
- [ ] PR live RSS source-health成功
- [ ] source registry fragmentを含めてsnapshot audit成功
- [ ] unchanged feedで新snapshot rowを作らない
- [ ] delivery stateがmonitorと分離され、ackは成功後だけ
- [ ] PR exact headでrepository gateにcorrectness/data-integrity blockerなし

## Non-goals

- FactSet本文全文の保存
- RSS itemをLLMでdedupeすること
- GDELTの削除
- 他ニュースソースの追加
